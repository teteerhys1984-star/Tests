# واجهة الفهرس (الصفحة الرئيسية)

هذا المجلد يحتوي على **تصميم ومولّد الصفحة الرئيسية** فقط. لا يغيّر أي شيء في
مجلدات الاختبارات: لا منطق تصحيح، ولا `EXAM_ID`، ولا روابط منشورة، ولا نظام
الإرسال إلى Google Sheets.

```
landing/
├── template.html        # التصميم كاملًا: HTML + CSS + JavaScript (بلا اعتماديات برمجية)
├── fonts/               # ملفات خط Cairo المتغير (WOFF2) المضمَّنة محليًا
├── generate.py          # يقرأ المجلدات المنشورة في _site وينسخ الخطوط ويبني _site/index.html
├── exams.json           # (اختياري) تصنيف يدوي لتجاوز التصنيف التلقائي (صف/مادة/فصل)
├── tests/test_generate.py   # اختبارات البنية والفصول والروابط والخط وبوابة الدخول (Python)
├── tests/gate.test.mjs      # اختبارات سلوك بوابة الدخول (Node، بلا اعتماديات)
├── scripts/password-hash.mjs  # حساب بصمة كلمة مرور جديدة للبوابة
├── scripts/build-exams.sh   # محاكاة خطوة بناء الاختبارات في النشر
└── scripts/verify-site.py   # تحقق شامل من الموقع الناتج بعد البناء
```

## تجربة الاستخدام: أربع خطوات

```
الصفوف  →  الفصل الدراسي  →  المواد  →  الاختبارات
```

* **الصفوف:** تسع بطاقات ملوّنة، لكل صف لونه ورقمه (بالأرقام الإنجليزية 1–9)، وعدد المواد
  والاختبارات المتاحة فيه، ونقاط ملوّنة توضّح المواد التي فيها اختبارات.
* **الفصل الدراسي:** عند فتح أي صف تظهر أولًا بطاقتان واضحتان فقط:
  **الفصل الأول** و**الفصل الثاني**، ولكل بطاقة رقمها وأيقونتها وعدد المواد
  والاختبارات فيه. الفصل الذي لا اختبارات فيه يظهر بوضع «لا توجد اختبارات بعد»
  لكنه يبقى قابلًا للفتح؛ فيظهر داخله كل مواد الصف بحالة «قريبًا».
* **المواد:** بطاقات أكبر مع أيقونة SVG لكل مادة (كتاب، فرجار، ذرّة، دورق،
  حوار) ولون خاص بها. المواد التي لا اختبارات فيها تظهر بوضع «قريبًا».
* **الاختبارات:** بطاقات واضحة فيها عنوان الاختبار ومساره وزر «ابدأ».

لا توجد قوائم منسدلة ولا أكورديون: الانتقال بين الخطوات يتم بمشاهدة كاملة مع
حركة خفيفة، ومسار تنقّل (فتات الخبز) أعلى الصفحة، وروابط قابلة للمشاركة:

```
/#g7              ← مشهد فصول الصف السابع
/#g7/s1           ← مشهد مواد الفصل الأول في الصف السابع
/#g7/s1/physics   ← مشهد اختبارات فيزياء الصف السابع — الفصل الأول
```

> **توافق خلفي:** الروابط القديمة بلا فصل مثل `/#g7/physics` ما زالت تعمل
> وتُفسَّر على الفصل الأول (`/#g7/s1/physics`)، فلا ينكسر أي رابط فهرس قديم.

خصائص أخرى: بحث فوري يتجاهل التشكيل واختلاف الألف/الياء/التاء ويشمل اسم الفصل،
زر رجوع في كل مشهد، دعم أزرار المتصفح (الرجوع/التقدّم)، اختصار `/` للبحث
و`Escape` للرجوع، تخطيط RTL كامل، واستجابة كاملة للهاتف والكمبيوتر.

الصفحة مكتفية بذاتها تمامًا: **خط Cairo المتغير (WOFF2) مضمَّن محليًا ضمن الموقع،
ولا صور خارجية، ولا خطوط من الإنترنت، ولا مكتبات خارجية، ولا أي طلب خارجي** —
وكل الأيقونات رموز SVG مضمَّنة في الملف.

## الطبقة الجديدة: الفصل الدراسي

الفصل الدراسي جزء من **بيانات الفهرس** لا من التصميم فقط:

* في `generate.py`: القائمة `SEMESTERS` (مفتاح، رقم، اسم، أيقونة، لون) هي المصدر
  الوحيد، و`SEMESTER_DEFAULT` يحدد الفصل الافتراضي.
* في الصفحة المولَّدة: لكل فصل مشهد مستقل `#view-sem-<الصف>-<الفصل>`، ولكل مادة
  مشهد اختبارات `#view-exams-<الصف>-<الفصل>-<المادة>`، ولكل بطاقة اختبار
  `data-semester="s1|s2"`، ولكل مشهد `data-semester` مطابق.
* في `landing/exams.json`: يمكن تثبيت فصل أي اختبار يدويًا عند الحاجة.

### كيف يُصنَّف فصل الاختبار؟ (بالترتيب)

1. حقل `semester` في `landing/exams.json` (أعلى أولوية). يقبل `1` أو `2` أو
   `"s1"` أو `"s2"`.
2. كلمات صريحة في عنوان الصفحة أو اسم المجلد، مثل: `الفصل الثاني`،
   `الفصل الثانى`، `الترم الثاني`، `semester 2`، `term 2`، `s2`، `sem2`.
   (وكذلك صيغ الفصل الأول: `الفصل الأول`، `semester 1`، `s1` …)
3. وإلا يُسند الاختبار إلى **الفصل الأول** (`SEMESTER_DEFAULT = 1`) — قاعدة آمنة
   ومتسقة. هذا ما ينطبق على **كل اختبارات المنصة الحالية**، لأنها كلها من الفصل
   الأول ولا تحمل أي معلومة فصل.

يطبع المولّد في سجل النشر عدد الاختبارات في كل فصل، وعدد ما أُسند افتراضيًا:

```
Semesters — الفصل الأول: 20, الفصل الثاني: 0
Semester default — 20 exam(s) had no explicit semester, assigned to الفصل الأول (SEMESTER_DEFAULT).
```

### كيف أضيف اختبارًا للفصل الثاني مستقبلًا؟

أضف مجلد الاختبار المعتاد، ثم اختر أحد الخيارين:

* **تلقائي:** اجعل عنوان الصفحة يحتوي «الفصل الثاني» (أو اسم المجلد يحتوي
  `semester2` / `s2`)، فيدخل تلقائيًا تحت:
  `الصف → الفصل الثاني → المادة → الاختبار`.
* **يدوي:** أضف في `landing/exams.json`:

```json
{
  "overrides": {
    "grade8-math-unit3": { "grade": 8, "subject": "math", "semester": 2 }
  }
}
```

لا يحتاج نظام الفهرس أي تعديل آخر، ولا تُنشر أي بطاقة وهمية.

## قاعدة ظهور المواد

مضبوطة في مكان واحد في أعلى `generate.py`، وتُطبَّق داخل كل فصل:

| المادة | الصفوف التي تظهر فيها |
| --- | --- |
| اللغة العربية | 1 – 9 |
| الرياضيات | 1 – 9 |
| اللغة الإنجليزية | 1 – 9 |
| الفيزياء | 7 – 9 فقط |
| الكيمياء | 7 – 9 فقط |

> لا تظهر بطاقة الفيزياء أو الكيمياء إطلاقًا في الصفوف من الأول إلى السادس.
> لتعديل القاعدة: غيّر الصفوف في قائمة `SUBJECTS` في أعلى `generate.py` فقط.

## كيف يُصنَّف اختبار جديد (الصف والمادة)؟

كما كان سابقًا: يقرأ المولّد `<title>` من `dist/index.html` لكل مجلد منشور،
ويستخرج الصف والمادة (اسم المجلد يُستخدم احتياطًا)، ثم يضع الاختبار في مكانه
تلقائيًا. **لا حاجة إلى أي تعديل يدوي عند إضافة اختبار جديد.**

إن كان عنوان اختبار لا يكفي لتصنيفه، أضف استثناءً يدويًا في `landing/exams.json`:

```json
{
  "overrides": {
    "grade7-physics-exam": { "grade": 7, "subject": "physics", "semester": 1, "title": "اختبار الفيزياء — الصف السابع" }
  }
}
```

وإن صُنّف اختبار في مادة لا تُعرض في صفّه، يطبع المولّد
`::warning::` في سجل النشر بدل إخفائه بصمت.

## بوابة الدخول (حاجز تجميلي)

عند فتح `/Tests/` لا تظهر المنصة: تظهر بطاقة صغيرة تطلب كلمة مرور. بعد إدخال
الكلمة الصحيحة يظهر الفهرس كاملًا (الصفوف ← الفصول ← المواد ← الاختبارات).

* **كلمة المرور الافتراضية:** `CloseYourEyes173`
* **أين تُحفظ الحالة:** في `sessionStorage` داخل المتصفح بمفتاح
  `tests-platform-gate-v1` وقيمة `open`. تبقى ما دام **تبويب المتصفح مفتوحًا**
  (حتى مع إعادة تحميل الصفحة أو التنقل بين المشاهد)، وتُنسى عند إغلاق التبويب.
  عند حجب التخزين في المتصفح تظهر البوابة عند كل تحميل، ويعمل الدخول عاديًا.
* **ما لا تحميه:** ليست مصادقة حقيقية. البصمة (FNV-1a) موجودة داخل صفحة HTML
  المنشورة، ويمكن استخراجها أو تجاوز البوابة تقنيًا (إزالة `hidden` أو حذف
  مفتاح التخزين). الهدف إبعاد الزائر العشوائي لا منع الوصول.
* **الاختبارات غير محجوبة:** البوابة موجودة في `_site/index.html` فقط. صفحات
  الاختبارات (`/Tests/<exam-folder>/`) لا تحتوي أي سكربت بوابة، فتبقى روابط
  الطلاب المباشرة تعمل كما هي بلا كلمة مرور.
* **بدون JavaScript:** لا يمكن فتح الفهرس (البوابة تحتاجه)، لذا تُعرض رسالة
  واضحة بدل صفحة فارغة. صفحات الاختبارات نفسها لا تتأثر.

### تغيير كلمة المرور

```bash
node landing/scripts/password-hash.mjs "كلمتك-الجديدة"
# PASSWORD_HASH = 0x........
```

ثم استبدل قيمة `PASSWORD_HASH` في `landing/template.html` (داخل
`<script id="gate-script">`) بالقيمة المطبوعة، وحدّث الوثائق. لا تُوضع أي أسرار
حقيقية في المستودع: البوابة تجميلية وكلمتها تُنشر مع الموقع.

## التشغيل والتحقق محليًا

```bash
# 1) بناء كل الاختبارات وتجميعها في _site (محاكاة خطوة النشر)
bash landing/scripts/build-exams.sh

# 2) توليد الصفحة الرئيسية
python3 landing/generate.py _site

# 3) اختبارات البنية والفصول والروابط وبوابة الدخول
python3 landing/tests/test_generate.py

# 4) اختبارات سلوك بوابة الدخول (تتطلب Node فقط، بلا حزم)
node landing/tests/gate.test.mjs

# 5) فحص الموقع الناتج (الروابط، EXAM_ID، الفصول، قاعدة المواد، الأرقام، البوابة)
python3 landing/scripts/verify-site.py _site

# 6) معاينة محلية
python3 -m http.server 8080 --directory _site
```

## الملفات التي يلمسها النشر

`.github/workflows/deploy.yml` لم يتغيّر: خطوة «Generate landing page» تستدعي
`python3 landing/generate.py _site`، وخطوات بناء الاختبارات والنشر نفسها لم
تتغيّر. كل تعديلات هذه الميزة محصورة في `landing/` (المولّد، القالب، الاختبارات،
السكربتات، الوثائق) دون أي تعديل داخل مجلدات الاختبارات.
