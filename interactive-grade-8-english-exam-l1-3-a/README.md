# Interactive Grade 8 English Exam L1-3 A

Independent Grade 8 · Semester 1 · English exam (`interactive-grade-8-english-exam-l1-3-a`). The original source is `../interactive-grade-8-english-exam-L1-3 A`; it is never imported at runtime or modified. `src/data/exam.ts` and the two source JPEGs are byte-for-byte copies. The source is excluded from both platform build entry points.

There are 54 multiple-choice, 7 true/false and 39 typed parts. Each part is worth one mark; a multi-part question can earn partial marks. Two local reading passages are in the bank; the hero and banner are JPEGs. There are no video or recorded-audio files: sounds use Web Audio. Original Google Fonts were replaced by local Cairo files bundled into the single-file build. The original contact links open `tel:` and WhatsApp; result delivery uses the existing Google Apps Script endpoint. Apart from these user-initiated/contact and submission links, the exam requires no external runtime assets.

## Source issues preserved and technical adaptations

- The source's Q13 and Q14 share a seven-blank paragraph; its original renderer mapped Q14 to blanks 1–3 instead of 5–7 and also rendered duplicate empty-stem fields. The published renderer maps Q13 to 1–4 and Q14 to 5–7 and removes the duplicates. The paragraph, keys, instructions and marks remain unchanged. Result/report/teacher numbering uses the actual Q14 blank numbers.
- Q22 part 2's displayed canonical answer is not among its source accepted strings; Q28's three full canonical answers (including the optional `(that)` notation) likewise do not match the shorter accepted strings. The independent grading adapter accepts the displayed canonical forms, with and without the optional word, in addition to all source alternatives. The original bank is unchanged. Typed responses still use exact normalized matching, not semantic grading: other valid paraphrases may not be accepted.
- The source passage has typography such as “21  century”, missing spaces after full stops and “trip,we”. Q30's explanation describes “have → had” as a present-perfect shift although “I have a headache” is present simple. These original educational strings are preserved rather than silently rewritten.
- The source allowed the teacher-key trigger during an attempt; this version exposes it only on welcome and results. The client-side password gate is a visibility barrier, not secure authentication or encryption. It uses the same teacher password as existing exams; the platform's public gate is unchanged.
- The source did not restore the current question on refresh or submit results to Sheets. This version persists the current question and uses a stable attempt ID and namespaced attempt, report and pending keys. It saves the pending payload before attempting delivery; retries use the reference contract and never block the results or report. Pending payloads contain student data on the device and are retried when the exam is opened.
- The published title is shown on welcome, results, the browser tab, reports, index and Sheets payload. Results are sent to the teacher; the original contact footer's browser-only statement was adjusted to reflect this.

## Development and checks

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run verify:build
```

Vitest checks source bytes and independence, grading and completion, storage, report/payload and retry/failure/timeout/flush using Mock Fetch only. The reference Apps Script is never contacted by these tests. `dist/index.html` is generated by Vite's single-file plugin and is the platform deployment artifact. The production app sends actual results to the configured endpoint; do not submit real or test data to it while developing.
